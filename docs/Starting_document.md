# Background:
A company has years of engineering and infrastructure design information stored in design files and related project documents. Users often do not know which files contain the information they need, and they do not want to learn file formats, schema details, query languages, or system-specific jargon.

# Constraints:
A broader architecture direction already exists, the files live in an existing repository, Connector and APIs can extract metadata/text/properties from supported files, extracted information can be stored in structured and/or semantic stores, and a chat-agent shell can call backend APIs or tools to expose a conversational plane for users.

# Use Case: 
We want a selected engineering manager or lead to be able to find a critical engineering parameter (e.g., a load limit, a material specification, or a compliance approval status) across 100+ project documents in under 10 seconds, with 100% confidence in the source, without opening a single design file (CAD) or tool (PDF viewer).

# Task:
As a Ninja developer, your task is to identify, clarify the requirements, any critical gaps or challenges – (5 mins), define the initial phase and create a system design diagram (10 mins), and get a working prototype of an MVP (40 mins).

# Scope:
Initial scope is just an MVP and NOT the final platform or solution.
